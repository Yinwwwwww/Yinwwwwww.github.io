skill · 04
腾讯 · 产品策划

任务背景

把产品落地经验分享转化为其他项目组可直接复用的结构化案例。

原流程与成本

展示文档与会议录制“讲过即消失”；人工整理结构不一，智能纪要又常缺少踩坑、真实数据和问答边界。

AI 实现方案

脚本拉取逐字稿，LLM 交叉理解逐字稿与展示材料，识别口径差异并按模板成文，经用户确认后新建 iWiki 页面。

{{ partial "skill-diagram.html" (dict "type" "sharing" "label" "产品落地经验分享转 iWiki 案例完整流程图") }}
关键设计决策
  • 逐字稿是一手事实，展示材料提供结构；数字冲突以展示材料口径为准并标注。

达成效果

AI 实现方案

先沉淀技术社区画像与 sourcing 方法，再将搜索、公开证据提取、方向匹配和候选人卡片整理封装为 Skill；接入 Aime 后，可在对话中输入岗位方向并直接获得候选人结果。

关键设计决策
  • 先理解社区运营模式、主流人群和招聘路径，再确定搜索来源，避免脱离社区语境进行无差别检索。

达成效果

反馈收集流程重构

workflow · 01
腾讯 · 产品策划

任务背景

将每日新增的用户需求与缺陷完整沉淀到 TAPD（需求与缺陷管理平台），并与已有事项或已上线能力建立关联，让反馈可统计、可排期、可闭环、可回访。

原流程与成本

反馈分散在共享表格、访谈材料和旧 Bot/TAPD，存在漏录、重复建单、字段与原始材料缺失；旧 Bot 直接理解非结构化对话建单，还会引入幻觉和字段不稳定，人工拆解、查重、补字段与搬图成本高。

AI 实现方案

以智能表单和多维表格保存原始事实，每日两次触发自动化入池 Skill；脚本、LLM 与 TAPD MCP 分别承担解析、判重和写入，人工只把关疑似重复与异常。

{{ partial "skill-diagram.html" (dict "type" "feedback" "label" "反馈收集流程重构完整流程图") }}
关键设计决策
  • 原始反馈先确定性落库，AI 不决定事实是否被保存；即使处理失败，记录仍可重试或人工补偿。
  • 已有记录只追加证据、不覆盖正文；“已实现”必须有发布或知识来源佐证，否则降级为新反馈。
  • 建单前再次检索，写入后回读真实字段；图片失败回退附件，任何不确定项交由人工确认。

达成效果

每日 2 次定时任务处理
约 2 个月持续运行
90+ 条原始反馈全部进入处理结果

新增、重复、已实现三类结果均可追踪，增量原始记录无遗漏。历史阶段另完成 100+ 条反馈录入及 200+ → 120+ 主单治理，三组数据口径独立、不合并计算。

平台数据运营看板

workflow · 02
腾讯 · 产品策划

任务背景

每周稳定回答平台趋势、失败归因、使用情况和成本四类问题，为 20+ 人产研测团队及管理层周会提供可比较、可行动的数据依据。

原流程与成本

初始只有粗略模板，指标、口径和取数方式未定义；整版交给 AI 一次生成会出现 SQL 报错或超时、口径漂移、长上下文幻觉与反复校对，完整产出约需 1.5 天。受合规限制，AI 也不能直连数据库。

AI 实现方案

将整版任务拆成四个独立模块，以模板、标准取数手册和模块 Prompt 锁定口径；人工执行 SQL，AI 基于真实回传数据出图与初步归因，再经人工核验和修改 SOP 合并发布。

{{ partial "skill-diagram.html" (dict "type" "dashboard" "label" "平台数据运营看板完整流程图") }}
关键设计决策
  • 看板结构高频局部变化，刻意保持半自动；稳定规则封装为节点 Skill，变化内容留在手册、Prompt 与人工控制点。
  • SQL 必须由人工执行，AI 只依据回传的真实结果出图和归因；四个模块独立运行，避免长上下文污染。
  • 范围、口径、前后周变化与异常值必须人工复核；指标变化只修改对应模块，并经过单独 SQL 测试与版本更新。

达成效果

8 周持续运营
约 1 小时单次出数，由约 1.5 天缩短
20+ 人团队与管理层周会使用

其中人工执行与核验约 30 分钟。模块化链路减少了 SQL 报错、口径漂移和重复校对，并支持从企微使用下降等异常中形成宣导动作、持续跟踪数据回升。

BOSS 直聘 HR 助手

workflow · 03
字节跳动 · HRBP

任务背景

将 BOSS 直聘上的候选人初筛、资格判断、标准回复和求简历串成可长期运行的自动化链路，让 HR 把精力集中在需要人工判断和深度沟通的候选人上。

原流程与成本

HR 需要逐条阅读候选人资料、对照岗位条件并重复回复。BOSS 没有 MCP，前端还通过图片化、图层隐藏文字等方式防抓取，AI 视觉读取和自动点击都不稳定，容易抓错内容或点错按钮。

AI 实现方案

用标准化脚本监听并筛选前端网络数据，把候选人必要字段传入 Coze 工作流；大模型只负责按岗位标准判断，结构化结果回传脚本后，再由脚本在 BOSS 执行回复、求简历或停止推进。

{{ partial "skill-diagram.html" (dict "type" "boss" "label" "BOSS 直聘 HR 助手完整流程图") }}
关键设计决策
  • 产品不是 Agent，也不是 MCP Tool；BOSS 无 MCP，整条链路由确定性脚本与 Coze 工作流共同完成。
  • 候选人信息通过前端抓包提取，按钮操作由脚本固定执行；不让 AI 视觉模型承担不稳定的页面抓取和点击。
  • 大模型只做语义筛选并返回受约束的结构化结果；Prompt 围绕格式、限制内容与 badcase 迭代 10+ 版后固化。

达成效果

抓包 + 脚本固定采集与页面动作
10+ 版Prompt 与 badcase 迭代
长期稳定自动筛选、回复与求简历

将不可靠的页面识别转为可重复的抓包与脚本动作，并把语义判断收敛到 Coze 工作流，最终形成可长期跑通的自动化筛选助手。
