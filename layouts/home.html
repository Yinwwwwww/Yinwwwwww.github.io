01
FEEDBACK GOVERNANCE

反馈自动入池

atap-feedback-to-tapd
腾讯 · 产品策划
01

任务背景

要解决的事

将每天新增的需求与缺陷完整、规范地沉淀到 TAPD，并与已有事项或已上线能力建立关联。

原流程与成本

反馈散落在共享表格、访谈材料和旧 Bot/TAPD；人工需要逐条拆解、查重、补字段、搬图片，且旧 Bot 直接理解对话建单，存在漏录和幻觉风险。

02

实现方案

以多维表格保存不可丢失的原始事实，再由脚本、LLM 与 TAPD MCP 分工完成解析、判重、分流和写回。

  1. 01解析反馈表
  2. 02检索多源记录
  3. 03三类分流
  4. 04追加或建单
  5. 05回读校验
关键设计决策
  • 原始反馈先确定性落库，AI 不决定事实是否被保存。
  • 已有项只追加评论与证据、不覆盖正文；“已实现”必须有发布或知识来源佐证。
  • 疑似重复和图片归属保留人工确认，跨系统写入后回读真实字段。
03

达成效果

每日 2 次定时增量处理
约 2 个月持续运行
90+ 条原始反馈全部进入处理结果

新增、重复、已实现三类结果均可追踪，原始记录无遗漏。历史阶段另以同一方法完成 100+ 条录入及 200+ → 120+ 主单治理，三组数据不合并计算。

02
RELEASE TRACEABILITY

发布反馈对账

atap-release-feedback-matcher
腾讯 · 产品策划
01

任务背景

要解决的事

回答“本期发布承接了哪些用户反馈”，为版本复盘、反馈关闭和用户回访提供依据。

原流程与成本

研发向发布计划与用户向反馈池长期分离；产品需要凭记忆跨两套系统逐项核对，关系无法追溯、复核。

02

实现方案

输入发布计划链接，拉全双侧数据，先识别明确来源引用，再进行从严语义匹配，输出需求与缺陷对照表。

  1. 01解析发布链接
  2. 02双侧分页拉全
  3. 03父子需求聚合
  4. 04来源与语义匹配
  5. 05三档结果
关键设计决策
  • 严格区分发布计划的 release_id 与反馈池 iteration_id，异常条数立即停止。
  • 显式来源引用优先；语义匹配比较功能模块和操作对象，不只看标题关键词。
  • 结果分为高置信、疑似、未找到，疑似项不硬判并交由人工复核。
03

达成效果

将依赖个人记忆的对账变成两张 7 列可追溯对照表和命中小结，支持一对多、多对一关系，为回访与反馈闭环提供统一入口。

03
FAILURE DIAGNOSIS

失败缺陷对账

atap-poster-failure-matcher
腾讯 · 产品策划
01

任务背景

要解决的事

判断运营海报中的 Error Run、Failed Task 是否已有对应缺陷，连接系统监控与用户问题。

原流程与成本

失败归因海报和反馈池互不相通；运营或产品需逐项阅读报错、再人工搜索缺陷，同一故障可能反复出现却无法识别。

02

实现方案

输入海报 HTML 与截止日，自动推算观察窗，逐条匹配失败项，最后按 TAPD 缺陷单聚合交付。

  1. 01解析失败海报
  2. 02推算 10 天窗口
  3. 03筛选候选缺陷
  4. 04逐条语义匹配
  5. 05按缺陷单聚合
关键设计决策
  • 只要求截止日，统一推算左闭右开的 10 天窗口，减少沟通并固定口径。
  • 匹配时同时比较模块、操作对象和报错现象，每条失败保留独立置信度。
  • 输出按缺陷单一单一行；未匹配项不强行入表，但必须披露数量。
03

达成效果

形成“失败项—缺陷单”标准化入口，既支持异常归因和重复问题识别，也通过总量对账与一单一行避免漏项和重复统计。

RELEASE COMMUNICATION

更新日志生成

atap-changelog-updater
腾讯 · 产品策划
01

任务背景

要解决的事

将产品与技术信息合并为面向用户的周度平台更新日志，并安全写入 iWiki。

原流程与成本

产品信息在周例会、技术信息在发布计划，人工拼合容易漏周、写错周；修改时还可能覆盖历史条目。

02

实现方案

以周例会上线能力为主、TAPD 缺陷为辅，校验周期后生成用户语言，经确认再执行新增或定点修改。

  1. 01定位目标周
  2. 02采集双源信息
  3. 03周期一致性校验
  4. 04生成用户日志
  5. 05确认后写入
  6. 06回读验证
关键设计决策
  • 双源周期不一致立即暂停，避免把不同周的信息拼在一起。
  • 写入前必须人工确认；先读旧页面，再决定新增或修改。
  • 新增只追加并按日期排序，修改只替换目标周，防止覆盖历史。
03

达成效果

把双源拼合、用户化表达和 iWiki 写入收敛为可校验流程，降低错周、漏项及误覆盖风险，形成可持续维护的更新日志。

KNOWLEDGE REUSE

分享案例沉淀

atap-share-to-iwiki
腾讯 · 产品策划
01

任务背景

要解决的事

把产品落地经验分享转化为其他项目组可直接复用的结构化案例。

原流程与成本

展示文档与会议录制“讲过即消失”；人工整理结构不一，智能纪要又常缺少踩坑、真实数据和问答边界。

02

实现方案

脚本拉取逐字稿，LLM 交叉理解逐字稿与展示材料，识别口径差异并按模板成文，经用户确认后新建 iWiki 页面。

  1. 01读取展示材料
  2. 02拉取会议逐字稿
  3. 03两源交叉核对
  4. 04按模板成文
  5. 05用户确认
  6. 06新建并回读
关键设计决策
  • 逐字稿是一手事实，展示材料提供结构；数字冲突以展示材料口径为准并标注。
  • 通过主题、日期、正文三点核对录制，匹配不上就停止，不用相似内容凑数。
  • 敏感信息中性化；每期新建页面不覆盖历史，写后检查章节、表格和父页面。
03

达成效果

将一次性分享转化为结构统一、口径可追溯的案例资产，并保留现场问答与可照搬清单，让经验从“听过”变为“可复用”。

DATA GOVERNANCE

AI 资产盘点

atap-ai-asset-inventory
腾讯 · 产品策划
01

任务背景

要解决的事

回答平台有哪些 AI 资产、谁创建、何时发布、权限如何，以及是否被引用或使用。

原流程与成本

Skill、MCP、知识库、测试专家、工作流分散在 3 个数据库；人工临时 SQL 依赖个人口径，错误不会报错却会直接进入汇报。

02

实现方案

先定义口径与可观测边界，再由用户执行标准 SQL，脚本还原工作流用量、合并结果，最终完成五项对账和台账输出。

  1. 01定义统计口径
  2. 02结构预检
  3. 03五类资产取数
  4. 04三跳还原用量
  5. 05五项对账
  6. 06台账与局限披露
关键设计决策
  • 工作流用量按 Run → Session/Task → Workflow 还原，并拆分主任务与子节点。
  • 知识库挂载不等于检索命中；Skill 缺少真实调用日志，不以安装或绑定冒充用量。
  • 人工执行 SQL 既适应合规限制，也是一道权限闸门；“无记录”与数值 0 分开表述。
03

达成效果

5 类资产统一明细口径
3 个数据库跨库取数
7 Sheet总览与明细台账

通过结构预检、构成加和、覆盖率和跨周交叉验证，避免“看起来合理”的静默错数，并将所有数据局限写入交付物。

INDUSTRY INTELLIGENCE

行业周报生产

weekly-report
腾讯 · 产品策划
01

任务背景

要解决的事

为游戏品质管理团队提供稳定、可信、可转化为产品机会的游戏测试与 AI 情报窗口。

原流程与成本

临时检索式生产依赖个人状态：来源不可考、链接失效、板块跑偏、同一事件重复，大厂官方动态也容易漏跟。

02

实现方案

将选题、检索、来源核验、事件去重、技术拆解和 HTML 输出固化为周度生产线，最终由人工复核发布。

  1. 01确认期号周期
  2. 02四板块检索
  3. 03官方源逐条核验
  4. 04事件去重归类
  5. 05技术三段式拆解
  6. 06HTML 与人工复核
关键设计决策
  • 只使用可访问、内容与日期相符的官方一手深链，不确定信息直接剔除。
  • 一个事件只进入一个板块；重点技术按“是什么—关键机制—适用边界”表达。
  • 固定板块与内容配额，引用编号全文连续，避免每期结构和质量随状态波动。
03

达成效果

10 期独立完成周报
200+ 成员部门覆盖
2 个方向转化为内部产品机会

周报不止做资讯搬运，行业线索进一步转化为团队共享上下文与“零侵入自动报 Bug”等产品规划输入；后两项仍处规划或待评审状态。

USER EDUCATION

新功能手册生成

atap-release-poster
腾讯 · 产品策划
01

任务背景

要解决的事

把研发向发布计划翻译成最终用户“一看就懂、照着能用”的图文新功能手册。

原流程与成本

原发版内容只列需求与缺陷，用户需要自行理解价值、入口和步骤；产品需人工筛选功能、确认路径、整理截图并重复排版。

02

实现方案

从发布计划中筛出用户可感知能力，按模块生成“价值、入口、步骤、配图”四件套，经截图与入口确认后输出统一 HTML。

  1. 01拉取当期需求
  2. 02剔除无感知项
  3. 03模块分组
  4. 04生成四件套卡片
  5. 05截图与入口确认
  6. 06HTML 预览交付
关键设计决策
  • 只有存在页面、入口、按钮或可见结果的功能才进入手册。
  • 操作步骤严格来自需求 description 原文；缺失时留空并提示补充，不自行编造。
  • 生成前回显保留项、剔除项、入口路径和截图归属，图片使用相对路径并支持灯箱。
03

达成效果

12 期累计负责发版内容
200+ 成员部门覆盖
定性反馈图文步骤更易阅读

统一了用户价值、功能入口和操作步骤的传播结构。12 期是发版清单与图文手册的总期数，不能表述为全部由该 Skill 自动生成。
